# `storage/` не покрывает половину того, что репа пишет на диск

> Создана 2026-09-05 по итогам сквозного ревью репозитория (13 линз, агенты). Дорожка A — числа не меняются. Объём M.

## Проблема

`storage/` объявлен слоем атомарного чтения-записи, но умеет ровно один формат — CSV
со схемой. Всё JSON-хозяйство пишется вручную.

Идиома `tmp = path.with_suffix(path.suffix + ".tmp")` встречается **18 раз в 12 файлах**:
`src/tickers.py:78,109`, `src/momentum/pipeline.py:84,256`,
`src/momentum/backtest.py:315,324`, `src/adjustments/detect.py:176`,
`src/adjustments/dividend_gaps.py:85`, `src/viz/site_builder.py:79`,
`src/cli/ingest_cmd.py:68,124,205,353`, плюс 5 в кэшах ingest.

Из них четыре копии в одном `ingest_cmd.py` — это буквально один блок «прочитать
manifest.json, обновить секцию, атомарно записать», отличающийся именем секции.
~60 строк копипаста в одном файле. При этом `pipeline.py:246` делает то же самое
через доменную функцию — то есть правильный образец рядом есть.

Один и тот же `json.dumps(..., ensure_ascii=False, indent=2, sort_keys=True) + "\n"`
повторён шесть раз.

Побочно: кэш внешних фетчеров пишется **не атомарно** —
`src/ingest/dividends/fetchers.py:61` и `scripts/backfill/fetch_tbank_dividends.py:97`
делают голый `write_text`. Ctrl-C посреди записи 700 КБ tbank-страницы оставляет
обрезанный HTML; при следующем чтении `_extract_dividends_payload` вернёт `None`,
фетчер молча вернёт `[]`, и tbank для этого тикера исчезнет из каскада без единого
сообщения. Runbook специально велит гонять `--refresh` в фоне ~10 минут — окно для
прерывания реальное.

## Что оказалось не так с постановкой

Треть задачи умерла до начала работы: **четыре из 18 мест — манифест, удалённый задачей
038**, плюс пятое в `pipeline.py`. Ещё пять принадлежат `task 040`, семь лежат в архивном
`mfd_backfill`, который вне `mypy` и вне графа импортов. Реальный объём — **8 мест в 7
файлах**. `json.dumps(...)` повторялся не шесть раз, а три.

**`write_jsonl_atomic` возвращать нельзя.** Коммит `f545587` удалил его намеренно,
исполняя `task 014` фазу 7. Хуже: удалённая версия писала с `separators=(",", ":")`, а
живой `data/tickers_unavailable.jsonl` — с дефолтными, так что наивное возвращение
переписало бы закоммиченный файл целиком. Единственный вызывающий оставлен как есть.

**`read_json` не нужен** — все места чтения сразу валидируют форму локально, обёртка
вокруг `json.load`, возвращающая `Any`, экономит две строки и теряет проверку.

## Что сделано

1. `storage/records.py`: `write_text_atomic` и `write_json_atomic(..., sort_keys=True)`.
   Восемь мест переведены.
2. **`sort_keys` вынесен в параметр не для красоты.** `_suspicious.json` и `_gaps.json`
   писались без сортировки, и порядок полей там — порядок полей датакласса, то есть
   читаемый. Сортировка переставила бы их по алфавиту; обоим передан `sort_keys=False`.
3. `viz/site_builder._atomic_write` переехал в `storage/` и стал `write_text_atomic`.
4. **Кэш внешних фетчеров стал атомарным** — это единственный пункт с настоящим сценарием
   отказа. Голый `write_text` на 700 КБ при Ctrl-C оставлял обрезанный файл, а `read_html`
   разбирал бы его в **меньшее число строк**, не падая: тихая недостача, не пустота.
   Для tbank это навсегда — кэш невосстановим, а скрипт пропускает существующие файлы.
   Проверено: все 317 закэшированных страниц читаются, риск не реализовался.
5. `SCORES_FIELDS`, `SCORES_CASTS`, `UNIVERSE_META_FIELDS` в `schemas.py`, подключены с
   обоих концов — `backtest.py` писал колонки инлайном, `site_builder.py` читал их
   руками написанными ключами, и ничто их не связывало.

`storage/manifest.py` не создан: манифеста больше нет, задача сама это предусматривала.

## Инвариант

`q_values.csv` байт-в-байт, `git status data/` пуст. Отдельно проверено, что
`data/tickers.json` проходит через новый писатель **побайтово идентично** — он
единственный закоммиченный JSON, который трогает эта задача.

Итог по репозиторию: 19 файлов, +190/−273 строки, тестов 692.
