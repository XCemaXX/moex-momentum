# Неучтённые сплиты и нечитаемый `_suspicious.json`

> Создана 2026-09-05 по итогам сквозного ревью репозитория (13 линз, агенты). Дорожка B. Объём M.

## Проблема

В `data/splits/` 11 файлов. `SBER`, `PHOR`, `ABRD` среди них нет, хотя сплиты были:

```
SBER  2007-07  total_return = -0.998945   (1:1000)
PHOR  2012-03  total_return = -0.904145   (~1:10)
ABRD  2012-10  фактор ~95
```

Детектор поймал **все три** — они лежат в `data/splits/_suspicious.json`. Их просто
никогда не разбирали: `data/splits/_acked.json` — пустой массив.

SBER и ABRD вне окна сайта. **PHOR влияет на публикуемые числа**: −90.4% за 2012-03
попадает в 12-месячное окно скоров на 2013-01 и 2013-02, а PHOR присутствует в
универсе все 164 месяца.

## Почему список не разбирают

4047 записей, 545 тикеров, единственная причина `abs_return_above_threshold`
(порог `|ret| >= 0.30` и `daily_value_rub >= 100 000`). Настоящих находок — **три**.
Отношение сигнал/шум 3 : 4044. Топ списка — MRKP (76), MRKZ (74), MRKU (71): сетевые
МРСК с ежедневными лимитными планками.

Проверенные кандидаты с «круглым» фактором оказались ложными: FLKO 2009-01
(165→16.75 за 3 дня на растущем объёме), UCSS 2019-03 (9945→1440 за 4 дня, объём
растёт), VTBR 2022-02-24 (обвал рынка).

Отдельно: `.claude/skills/update_monthly_data/references/recompute_and_build.md:26`
утверждает, что файл append-only и `git diff` показывает ровно новые флаги. Это
неправда — `src/adjustments/detect.py:174` пишет полный пересчитанный список
(коммит `c07c91c`: 19787 insertions, 5682 deletions). Инструкция ведёт ревьюера в
пропуск находок.

## Поправка к исходной постановке

Было написано «SBER и ABRD вне окна публикации». Вывод верный, **причина неверная**.
ABRD внутри окна; спасает его не окно, а разрыв торгов: сентябрь 2012 не торговался
целиком, `to_monthly_close` вставил gap-строку, `total_return` за 2012-10 стал NaN, и
правило 13 непрерывных закрытий выбросило бумагу из универса на год. Первый скор ABRD —
2013-10.

PHOR не спасло ничто: его остановка не покрыла ни одного календарного месяца целиком
(февраль торговался до 15-го, март — с 26-го), и `pct_change` посчитался прямо через сплит.

## Ошибка, пойманная при записи

Первая версия файлов была записана как `1000,1` вместо `1,1000`. По конвенции
`cascade_for_dates` умножает досплитные даты на `before/after`, то есть это умножило бы
цену Сбербанка 2007 года на тысячу вместо деления. Поймано сверкой с существующей записью
`GMKN 1,100,forward`. После правки ряды непрерывны:

```
SBER  2007-07-10 adj=102.500  → 2007-07-20 adj=109.20   +6.54%  (10 дней остановки)
PHOR  2012-02-15 adj=1001.30  → 2012-03-26 adj=922.00   -7.92%  (40 дней)
ABRD  2012-08-30 adj= 64.070  → 2012-10-02 adj= 67.07   +4.68%  (33 дня)
```

## Результат по числам

`PHOR` за 2012-03: **−90.4% → −4.1%**. Вместо скачка Q4→Q1 бумага стабильно в Q1 все
четыре месяца (2012-12 … 2013-03).

| | было | стало |
|---|---:|---:|
| Q1 | 12.764948 | 12.768125 (+0.025%) |
| Q2 | 3.069649 | 3.048733 (−0.681%) |
| Q3 | 1.911038 | 1.916411 (+0.281%) |
| Q4 | 0.314335 | 0.315400 (+0.339%) |

Величина — шум четвёртого знака. Чинилось не ради неё: бумага с рекордным дроблением
систематически объявлялась аутсайдером момента.

## Детектор: классификация вместо сужения

Сужать детектор было бы ошибкой. Разбивка его флагов:

```
limit_move        2798   планки неликвидов, кризисы
board_change      1227   смена торговой доски между соседними днями
near_dividend       16   выплата в пределах ±5 дней
sustained_rebase     8   кандидаты в сплиты
```

Те 1227 флагов на смене доски — единственное место, где численно виден дефект SMAL из
`task 037`, а 16 около дивиденда — кандидаты на ошибку якоря ex-даты из `task 036`.
Поэтому классификация сделана **слоем над** детектором, а не заменой его порогов.

### Фильтр `sustained_rebase`

Четыре независимых признака должны согласиться: величина ребейза по медианам 20 дней до и
после; доля, объяснённая **одним** днём (отсекает планки и сползания); близость к круглому
множителю; плоскость плато. Плюс требование остановки торгов ≥6 дней.

Пороги калиброваны на **14 подтверждённых событиях** — 11 закоммиченных сплитов плюс наши
три. **Recall 14/14**, включая обе стороны: `VTBR` 5000:1 (дневная доходность +466 282%)
и `IRAO` 100:1 проходят наравне с дроблениями, потому что все пороги на логарифме.
Прибито тестом `test_known_splits_are_classified_as_rebase`.

Записанная дата сплита не всегда торговый день — `BELU` детектируется на два дня позже,
`ROLO` на день. Сопоставление окном `SPLIT_MATCH_DAYS = 5`.

### Гейт по обороту обходится для кандидатов в сплиты

Обнаружено при прогоне: гейт `MIN_DAILY_VALUE_FOR_DETECT` отсекал 7 из 9 кандидатов
**до** классификации, то есть сплит на малоликвидной бумаге детектор не показал бы вовсе.
Согласие четырёх признаков — фильтр сильнее оборота, поэтому `sustained_rebase` теперь
проходит вперёд гейта.

## Триаж закрыт

Все 9 кандидатов разобраны и записаны в `data/splits/_acked.json` с причиной:

- **7** закрыты разрывом торгов (68…1520 дней) — месяц резолвится в NaN, вниз по течению
  шаг не читается.
- **ORSBP 2007-07-27** — не сплит: 27.444 держалось на сделках по 100 бумаг, затем 50 дней
  тишины и реальные торги по 2.7-4.15. Множитель 8.8 не соответствует ни одному изменению
  номинала. В универс не попадает ни разу (0 месяцев со скором).
- **NGSBP 2008-06-07** — не сплит: множитель 1.5 не соответствует изменению номинала,
  внутридневной диапазон 0.991-1.294 на обороте 29.7 тыс. ₽. 0 месяцев со скором.

Очередь `sustained_rebase` после этого — **пусто**.
