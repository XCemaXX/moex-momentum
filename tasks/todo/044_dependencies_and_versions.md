# Зависимости, версии, настройки инструментов

> Создана 2026-09-05 по итогам сквозного ревью репозитория (13 линз, агенты). Объём M. Числа не меняются (кроме отдельно помеченных пунктов).

## Констрейнты не защищают от того, от чего должны

| пакет | объявлено | в локе | проблема |
|---|---|---|---|
| pandas | `>=2.2` | **3.0.2** | диапазон спанит границу 2→3, где сменились дефолты Copy-on-Write и строковый dtype |
| plotly | `>=5.22` | **6.7.0** | диапазон покрывает plotly.js от 2.x до 4.x, а закоммичен бандл 3.5.0 |
| numpy | **не объявлена** | 2.4.4 | импортируется напрямую в `signals.py`, `significance.py`, тестах |
| beautifulsoup4 | `>=4.12` | 4.14.3 | **ноль употреблений** в репо; тянет 5 пакетов |

Про plotly отдельно: SHA-тест бандла проверяет только, что файл не подменили. Он **не
поймает рассинхрон** — при `uv lock --upgrade` поедет Python-сторона, а файл останется.
Сузить до `>=6.7,<7` и добавить ассерт на `plotly.__version__` рядом с SHA.

**plotly 7 брать нельзя:** сменён движок цвета TinyColor → culori, цвета текста и
границ выбираются по контрасту WCAG, что даёт переключения тёмное↔белое на насыщенных
заливках — бьёт по подписям Sankey. Плюс plotly.js 4 требует Node ≥22, локально 18.19.1
(EOL). Промежуточный безопасный шаг при желании свежести — plotly 6.9.0 / plotly.js 3.7.0.

## CI использует не тот флаг

`uv sync --frozen` означает «синхронизируй по локу, не обновляя его» — он **не
проверяет**, что лок соответствует `pyproject.toml`. Правишь зависимость, забываешь
перелочить — CI зелёный, окружение старое. Нужен `--locked`.

Тот же дефект в `scripts/setup.sh:30`: `uv sync --frozen 2>/dev/null || uv sync` —
ошибка подавлена, фолбэк тихо резолвит заново и **перезаписывает `uv.lock`** в свежем
клоне.

## Что ещё

- **Даровое:** `filterwarnings = ["error"]` — замерено, 619 passed / 0 warnings,
  включается бесплатно. Плюс `--strict-markers --strict-config`.
- `.python-version` отсутствует; `requires-python = ">=3.12"` без верхней границы —
  на машине с 3.13/3.14 `uv sync` выберет другую ветку резолюции из того же лока.
- `pip install uv` в обоих workflow без пина. Заменить на `astral-sh/setup-uv` с пином
  и кешем.
- mypy не покрывает `scripts/` (`files = ["src"]`), хотя два скрипта оттуда считают
  числа для сайта в CI. Там же два **мёртвых** `# type: ignore[arg-type]`
  (`compute_topn_fan.py:65,88`) и три настоящие ошибки в `compare_formulas.py:68,132,181`.
- `pages.yml` ставит dev-зависимости — нужен `--no-dev`.
- `pytest-cov` объявлена и нигде не включена.
- ruff: дешёвый добор `C4, SIM, PERF, DTZ, PTH, FURB, A, W, NPY, TID, ISC, RET` —
  суммарно ~34 механические правки. `DTZ` и `PD011` смотреть глазами: касаются кода,
  считающего даты и серии.
- npm: `package-lock.json` в gitignore — сборка бандла невоспроизводима, транзитивное
  дерево не зафиксировано. Коммитить лок, `npm ci`. esbuild 0.24.0 (2024-09) → 0.28.2.
  jsdom в `dependencies` вместо `devDependencies`, отстал на 8 мажоров.
- actions/checkout и setup-python: v6 → v7.

## Бандл трогать не надо

Пересобран независимо — sha256 совпал байт-в-байт, сборка воспроизводима. Замеренные
варианты оптимизации: `--legal-comments=none` −365 B, `--drop:console` −269 B,
`--target=es2020` **+39 B**, всё вместе −634 B raw / −284 B gzip. Это **0.05%**.
1.23 МБ — близко к полу для scatter + bar + sankey. Отделять sankey во второй бандл
плохо: сейчас один файл кешируется между всеми восемью страницами.
