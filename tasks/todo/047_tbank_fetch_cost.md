# Стоимость сбора tbank

> Создана 2026-09-05 по итогам сквозного ревью репозитория (13 линз, агенты). Объём S на главный пункт. Отложено автором в сессии 2026-09-01, теперь измерено.

## Что происходит сейчас

**Обычный запуск** (`scripts/backfill/fetch_tbank_dividends.py`): 316 тикеров с
существующим `.html` пропускаются мгновенно. Остальные **718 запрашиваются каждый
раз** — провалы не кэшируются, а `.fill_cache/tbank/_failures.json` (718 записей, все
`not_found`) скриптом не читается. Итог: ~718 запросов и 359 секунд чистого
`time.sleep` ради нуля новых данных.

**`--refresh`**: 1034 запроса, 316 отдают HTML средним размером 1.65 МБ (median 1.63,
max 1.97) — **520 МБ трафика за прогон**. Дельту запросить нельзя в принципе: страница
отдаёт всю историю одним bootstrap-блобом, параметра даты нет. Единственный рычаг —
**кого** спрашивать, не **что**.

## Профиль

| компонент | цифра |
|---|---|
| `SLEEP_BETWEEN = 0.5` × 1034 | **517 с** |
| скачивание 520 МБ | 80–210 с |
| чтение с диска + regex + `json.loads` 316 страниц | **6.1 с** |
| запись на диск | единицы секунд |

ЦПУ и парсинг ни при чём. Узкое место — self-imposed sleep и объём HTML.
`SLEEP_BETWEEN = 0.5  # seconds -> 2 req/s` (`fetch_tbank_dividends.py:35`) — **выдуманная
константа**: ни в коде, ни в скилле нет ни одного замера 429.

Полезная плотность: из 520 МБ HTML извлекается **359 КБ** JSON (1843 записи по 316
тикерам), коэффициент **1448×**. В `data/dividends/` доживает 464 строки.

## Ранжирование по «выигрыш / риск сломать данные»

**1. Не спрашивать тикеры, у которых страницы нет. Выигрыш 69% запросов. Риск ~0.**

Список уже существует и уже пишется — 718 записей `not_found`. Экономия **359 с с
каждого прогона**, включая «дешёвый» без `--refresh`, где это единственная трата.
Пропущенный 404 и несделанный запрос дают одинаковый результат — данные измениться не
могут.

Деградация одна: тикер появился в каталоге tbank после последнего полного обхода.
Лечится флагом `--full` (раз в квартал или при пополнении `tickers.json`) и полем
`checked_at` с TTL.

**Ключевая деталь:** файл лежит в `.fill_cache/`, которая не коммитится — после
`git clone` списка нет. Вынести в `data/dividends/_tbank_no_page.json`. Это заодно
попадает в цель «объяснения расхождений источников живут в репе»: «tbank не покрывает
эти 718 имён» — ровно такое объяснение, и сейчас оно живёт в невоспроизводимом кэше.

**2. Хранить извлечённый payload, а не HTML. Выигрыш 520 МБ → ~2 МБ. Риск low.**

Обязательная митигация: класть весь bucket `stores.investDividends.{T}`, а не готовые
записи — тогда переживают все брокерские поля (`declared`, период, тип выплаты).
Sanity-check в `fetch_tbank_dividends.py:93` работает по `r.text` в памяти, до записи,
так что логика «перезаписывать только при успешном payload» сохраняется. Экономии сети
не даёт — чисто дисковая мера.

**3. Ополовинить `SLEEP_BETWEEN` — только после замера. Риск medium (доступ, не данные).**

После п.1 остаётся 316 запросов = 158 с сна. Снижение до 0.25 срежет ещё ~80 с. Но
лимит не измерен: нужен осознанный прогон на 30–50 тикерах с логированием статусов.
Без замера это угадывание, а цена ошибки — блокировка IP на весь месячный refresh.

**4. Параллелизм — не делать до п.1.** После него остаётся ~5 мин, 4 воркера дадут ~2.
Выигрыш маленький, а цена — не «добавить asyncio», а переписать аккумуляцию: сейчас
там общий мутируемый `failures: dict` (`fetch_tbank_dividends.py:57`) и общие счётчики;
при наивном переносе на потоки `_failures.json` станет неполным.

**5. Сузить до ликвидной вселенной — НЕ делать.** `UNIVERSE_TOP_N_LIQUID = 100` —
скользящий срез, в 12-месячное окно входят имена, сегодня вне топ-100. Пропущенный
дивиденд у такого имени всплывёт как ошибка ранжирования через год, когда связь с
решением потеряна. Худшее отношение выигрыш/риск в списке.

**6. Дельта по датам — невозможна.** Страница не параметризуется.

## Целевое состояние

После п.1–2 ежемесячный `--refresh` — ~316 запросов, 3–5 мин, ~520 МБ трафика и **~2 МБ
на диске** вместо 520.

## Заодно

`src/ingest/dividends/yahoo.py:65` — `meta.get("currency", "RUB")`: дефолт не
срабатывает на `null`, а в кэше **32 из 266** payload'ов имеют `meta.currency = null`
(AVAZ, BISV, KRSG, MOTZ, OFCB, GRAZ). Повторный прогон каскада вернёт в данные дефект,
исправленный коммитом `9b0f34e`. Нормализовать на входе:
`(meta.get("currency") or "RUB").upper()` + `SUR -> RUB`, как уже сделано в
`tbank.py:106` и `iss.py:90`.

`_adjust_external` (`cascade_merge_dividends.py:136-163`) — сплит-коррекция внешних
источников — локальная замыкающая внутри `main()`. Её нет ни в `YahooFetcher`, ни в
`TbankFetcher`, ни в `fill.py`. Как только кто-то добавит их в `fetcher_map` в CLI,
коррекция тихо исчезнет, и по тикерам со сплитами (GMKN ×100, VTBR ×5000) записи уедут
на порядки. Та же судьба у чтения `_external_blacklist.json`.
